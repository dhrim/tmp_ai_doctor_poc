# AI주치의 (RWD기반 AI 건강 주치의)

스케일업 TIPS 과제(RS-2024-00410739) 3차년도 시스템 구축 레포. **agent와 사람이 함께 쓰는 공용 작업 공간**이다.

이 문서는 **프로젝트 참여자 전원(agent·사람)에게 적용되는 공통 규칙**이다. 자기 역할 문서는 그다음에 읽는다.

## 문서 체계

| 문서 | 적용 대상 | 내용 |
|---|---|---|
| `README.md` | 전원 (agent·사람) | 공통 규칙 — 이 문서 |
| `AGENTS.md` | agent 전체 | agent 공통 규칙 + 역할별(Planner·Engineer·Verifier·Executor) 지침 |
| `CLAUDE.md` | Claude | Claude에만 해당하는 사항 |
| `CODEX.md` | Codex | Codex에만 해당하는 사항 |
| `GEMINI.md` | Gemini | Gemini에만 해당하는 사항 |
| `HUMAN.md` | 사람 | 사람에게만 해당하는 사항 |

읽는 순서: `README.md` → (agent면) `AGENTS.md` → 자기 이름 문서 / (사람이면) `HUMAN.md`.
같은 내용을 여러 문서에 중복해 적지 않는다. 규칙이 바뀌면 해당 문서 하나만 고친다.

## 과제 전제

- 시스템: hCDM(비식별 임상데이터)에 근거해 환자 개인의 의료 질문에 답하는 시스템.
- 1·2차년도 산출물은 실체가 없다("없음" 선언). 기존 보고서는 참고용일 뿐 작업 기반이 아니다.
- BERT는 설치만 하고 호출하지 않는다. LLM은 의료특화 Gemma(수령 전에는 일반 Gemma).
- 일정: 8월말 구현 완료 → 9월 첫주 성능시험(MedQA·PTF) 1회로 종료 → 해남 API 10월 마감.
- 작업 범위: 시스템 구축 → 성능시험 → 인증 → 패키징. IRB·인증 절차·연차보고서 작성은 별도 트랙(기술 지원만).

## 저장소·경로 규칙

- **이 레포(`ai-doctor`)의 정본(main)은 누구도 직접 편집하지 않는다 — agent도 사람도.** 작업은 각자 브랜치/worktree에서 하고, PR로 올린다.
- **참여자는 각자 독립된 워킹 경로에서 작업한다.** 그 경로 밖은 수정하지 않는다. 꼭 필요하면 읽기만 한다.
  - Claude: `D:\workspace\claude`
  - Codex: `D:\workspace\codex`
  - Gemini: `D:\workspace\gemini`
  - 사람: 각자 지정한 경로
- 워킹 경로 하위 구조: 정본 레포의 clone(`<워킹경로>\ai-doctor`)과, 레포와 무관한 임시 산출물 공간을 둔다. 레포 작업은 clone 안에서, 그 외 작업은 워킹 경로 안에서 한다.
- 공용 드라이브(W:, 네이버웍스)는 읽기 전용 참조.

## 레포 구조

```
README.md / AGENTS.md / CLAUDE.md / CODEX.md / GEMINI.md / HUMAN.md   규칙 문서
work/     태스크별 핸드오프 (요청 → 결과). 작업 중 파일
tools/    스크립트
src/      시스템 코드
```

프로젝트 문서(요구사항·설계·결정)는 레포가 아니라 **노션**에 있다. 레포에는 사본을 두지 않는다.

## 산출물을 어디에 두는가 (불변 원칙)

- **작업 기록** → 노션
- **문서로 된 작업 결과물** → 노션 (정본)
- **코드·스크립트** → 이 레포(GitHub)
- 결과물 파일의 기본 위치는 노션이며, **코드·스크립트 실행에 필요한 파일만** 레포에 둔다.
- 파일 크기가 너무 크면 임의로 올리지 말고 **사람에게 묻는다.**
- **문서를 참조할 때는 노션에서 직접 읽는다.** 레포에 사본을 두지 않는다.

## 기록 보존·버전 규칙

- **기존 파일과 기존 노션 페이지를 수정·삭제하지 않는다.** 한 번 작성된 것은 기록으로 남긴다.
- 수정이 필요하면: 복사본을 만들고 이름·제목 뒤에 `_01`, `_02`… 를 붙이거나, **git으로 버전 관리한다.**

## 데이터·보안

- hCDM은 read-only이며 PHI(개인건강정보)의 프록시로 취급한다. 외부 전송 금지.
- 제품(구축 시스템) 코드에 외부 상용 LLM API(Claude/GPT/Gemini 등)를 넣지 않는다. 내부 서빙 Gemma만 사용한다. (개발 도구로 쓰는 것은 허용)
- 레포에 넣지 않는 것: 토큰·키 등 비밀정보, 대외비 원문(계획서·연차보고서), hCDM 데이터 일체.
- 해남(아이쿱) 트랙은 InBody·악력계 데이터만 API로 수신한다.

## 일하는 방식

- **모든 것은 Plan-Do-Verify로 진행한다. 예외 없음.** 문서·코드·설정 전부. 검증 완료가 작업 완료의 조건이다.
- 개발은 **PEV-E**(Planner–Engineer–Verifier + Executor). 검증자는 생산자와 다른 회사 모델을 쓴다.
- 합격 기준의 출처는 계획서와 거기서 도출된 요구사항이다. 기준이 없으면 그 작업에서 직접 만든다.
- 검증 이터레이션은 최대 5회. 동일 쟁점이 2회 반복되면 사람 판단을 요청한다.
- **git 머지는 사람만 한다.** agent는 PR 생성까지.
- 초기에는 모든 것에 사람 승인을 받고, 진행하며 자동승인을 넓힌다.
- SI식(모든 것을 사전에 정하고 문서화)을 배제한다. 목적은 워킹 시스템, 성능, 기준을 통과한 결과물, 필요할 때 참조 가능한 문서다.
- 고정 문서 템플릿은 두지 않는다. 필요한 내용이 담기고 이해되면 된다.

## 소통

- 모든 소통·산출물은 한글.
- 사람은 controller agent와만 직접 소통한다. 다른 agent에 대한 지시는 controller가 지침 문서와 작업 문서로 전달한다. 같은 지시를 사람이 반복하지 않게 하는 것이 controller의 책임이다.
